# Improvement Roadmap (2026-10)

The improvement plan that came out of a brainstorm and review session on 2026-10-03. The phases are ordered by dependency: each phase makes the next one safer to do. Every finding was checked against the code as of commit `32bad01` (v1.4.5).

## Verified findings that drive this plan

| # | Finding | Evidence |
|---|---------|----------|
| F1 | Switching is global. `--auto-mode` → `auto_switch_php` → `brew unlink` + `brew link --force`, and if FPM is enabled it also stops the other PHP-FPM services and restarts or starts the new one. So a `cd` in one terminal changes PHP (and FPM) for every terminal and IDE. | `lib/commands.sh:156-178`, `lib/auto-switch.sh:368-406` |
| F2 | The auto-switch hook spawns the full `phpswitch` script on every `cd` into a cached directory that has a version, even when the version already matches. Its own detection checks only `$PWD`, not parent directories. A shell opened in `project/src` caches the directory as "no version" and never switches. A `.php-version` added later to a directory cached as empty is never picked up. | `lib/auto-switch.sh:100-145` |
| F3 | The `--update` integrity check is a no-op. `EXPECTED_SHA256` is a `TODO_...` placeholder, so the comparison is skipped. If `shasum` is missing, the check is bypassed. The download comes from `master`, not a tag. | `lib/commands.sh:585-620` |
| F4 | The formula in this repo has `sha256 "TODO_CALCULATE_AFTER_RELEASE_TAG"`. `tools/release.sh` patches it at release time and copies it to the tap, so the copy in this repo is only correct after a release. Installing straight from this repo fails. | `Formula/phpswitch.rb:5` |
| F5 | The version is defined in two places: `PHPSWITCH_VERSION` in `config/defaults.sh` (used by build and `--version`) and the `# Version:` header in `phpswitch.sh` (used by `tools/release.sh`). They can drift. | `config/defaults.sh:5`, `tools/release.sh:28` |
| F6 | Build outputs are tracked in git although `.gitignore` lists some of them: `phpswitch-combined.sh` (root and `phpswitch/`), `phpswitch/php-switcher.sh` (dev copy). There's also a stale `phpswitch/prepare-release.sh-mute`. | `git ls-files` |
| F7 | Test coverage is thin: 7 bats tests for about 4,400 lines, and no CI. | `tests/*.bats` |
| F8 | Many interactive "try with sudo?" fallbacks. `sudo brew services` changes ownership of Homebrew files, which `fpm.sh` later has to repair. | `lib/fpm.sh:56-82,148-160`, `lib/extensions.sh:128`, `lib/auto-switch.sh:50,354` |
| F9 | `commands.sh` is 1,266 lines and mixes dispatch, the menu, install, uninstall and update. | `lib/commands.sh` |

The `sleep 1` loop in `core.sh:280-284` is a timeout guard for `brew search`, so it's intentional and not on this list.

## Phase 0: Repo hygiene ✅ (done 2026-10-03, branch `chore/phase0-hygiene`)

**Goal:** a clean tree where only source and the release artifact are tracked.

- Stop tracking the dev and combined build outputs: `git rm --cached phpswitch/php-switcher.sh phpswitch-combined.sh phpswitch/phpswitch-combined.sh`, then add `phpswitch/php-switcher.sh` to `.gitignore`.
- Remove `phpswitch/prepare-release.sh-mute`, or restore it if it's still needed.
- Commit the pending `core.sh` fix (`grep -Eo 'php@[0-9]+\.[0-9]+' | sort -u`) and rebuild `php-switcher.sh`.
- Replaced the `test.sh` / `test2.sh` scratch scripts with `tests/03_versions.bats` and a fake `tests/helpers/bin/brew`. This brings the fake `brew` forward from Phase 1.
- Single source of truth for the version: `PHPSWITCH_VERSION` in `config/defaults.sh`. `tools/release.sh` now reads and writes only that value. The `# Version:` header in `phpswitch.sh` just points to it. The built artifact's header is still generated by `build.sh`.

**Acceptance:** `git status` is clean after `./build.sh`, and `--version` and `release.sh` read the same value.

## Phase 1: Test harness and CI ✅ (done 2026-10-03, see [[concepts/testing]])

**Goal:** refactor the riskier phases with a safety net in place.

- **Fake `brew`:** `tests/helpers/bin/brew` is a stub script, placed first on `PATH`, that logs calls and returns fixture output for `search`, `list`, `--prefix`, `link`, `unlink` and `services`.
- **Isolated `$HOME`:** every test runs with `HOME=$BATS_TEST_TMPDIR/home`, so rc-file patching and the cache can be checked without touching the real machine.
- **New suites:**
  - `03_version.bats`: version normalization, `core_get_available_php_versions` parsing (regression for the `brew search` fix), and the switch calling link/unlink in the right order.
  - `04_auto_switch.bats`: `.php-version`, `.phpversion`, `composer.json` `require.php`, `.tool-versions`, and nested directories.
  - `05_shell.bats`: rc patching for zsh, bash and fish, including idempotency and backups.
  - `06_cli.bats`: flag dispatch, exit codes, `--help` and `--version`.
- **GitHub Actions** (`.github/workflows/ci.yml`, `macos-latest`):
  - shellcheck on an explicit file list: the built artifact (whole-program view), `lib/*.sh`, `build.sh`, `phpswitch.sh`, `tools/release.sh` and the fake brew. (`tools/fix-permissions.sh` was excluded for a syntax error until it was deleted on 2026-10-04.)
  - `bats tests/`
  - Build sync check: run `./build.sh`, then `git diff --exit-code php-switcher.sh`. The build currently has no timestamps, so it is deterministic. Keep it that way.

**Acceptance:** CI is green on master and a PR that forgets to rebuild fails.

## Phase 2: Release and update hardening ✅ (done 2026-10-03, see [[concepts/release-and-update]])

**Goal:** what users install is exactly what was released, and it's verified (fixes F3, F4).

- `tools/release.sh` builds the artifact, tags `vX.Y.Z`, and creates a GitHub Release with `php-switcher.sh` and `php-switcher.sh.sha256` as assets. It then updates the formula's `url` and `sha256` automatically.
- `--update` changes:
  - Detect a Homebrew install (script path under `$(brew --prefix)/Cellar`) and tell the user to run `brew upgrade phpswitch` instead of overwriting.
  - Otherwise, use the GitHub API to find the latest release, download the asset and its `.sha256`, verify with `shasum -a 256`, and refuse if the hashes don't match or `shasum` is missing.
  - Remove the `TODO` placeholder logic entirely.
- Optionally run this in a CI release job triggered by a `v*` tag.

**Acceptance:** a tampered asset is rejected (`tests/08_update.bats`). A CI formula install was dropped because the repo formula only becomes valid after a release; the repo copy is now synced to the tap's working v1.4.4 values.

**Release state found on 2026-10-03:** the latest GitHub release is tagged `1.4.5` (no `v`) and has **no assets**. The tap ships v1.4.4. The next release must go through `tools/release.sh` so that `--update` has a checksum to verify against.

## Phase 3: Per-shell switching and a fast hook (v2.0)

**3a ✅ (2026-10-03):** `init`, the wrapper, the hook, and `use`/`local`/`global`. See [[concepts/shell-integration]]. **3b ✅ (2026-10-03):** `--install-auto-switch` writes the `eval` line for the login shell and migrates legacy blocks from every rc file, all-or-nothing.

**Goal:** fix F1 and F2. This is a breaking change.

**Design constraint:** a child process can't change its parent shell's `PATH`, so per-shell switching needs a shell function loaded from the rc file:

```sh
eval "$(phpswitch init zsh)"   # or bash; fish: phpswitch init fish | source
```

`phpswitch init <shell>` prints:

- A `phpswitch` wrapper function. For `use`/`shell` subcommands it evaluates the output from the binary to rewrite `PATH`, putting `$(brew --prefix)/opt/php@X.Y/bin` and `sbin` first and removing any previous php entry. All other commands pass through.
- A lightweight `chpwd` / `PROMPT_COMMAND` / fish `--on-variable PWD` hook written in pure shell. It walks up from `$PWD` looking for `.php-version` or `.tool-versions`, compares the result with `$PHPSWITCH_CURRENT`, and only edits `PATH` when the version changes. No subprocess is spawned in the common case. `composer.json` still needs parsing, so it runs the binary only when no explicit version file is found.

Modes:

| Command | Effect |
|---------|--------|
| `phpswitch use 8.2` / `phpswitch shell 8.2` | Current shell only (`PATH`) |
| `phpswitch global 8.3` | Current behaviour: `brew link`. Still needed for FPM, Valet and IDEs. |
| `phpswitch local 8.2` | Writes `.php-version` in the current directory |

Migration:

- `phpswitch init --migrate` (or the first run of v2) finds the old `export PATH=...php@...` lines and old `phpswitch_auto_detect_project` blocks in rc files. It backs them up and replaces them with the single `eval` line.
- Remove the directory cache file (`directory_cache.txt`). It isn't needed once the hook is pure shell.

**Decision (2026-10-03):** in v2, auto-switch defaults to **per-shell**. This matches asdf, pyenv and nvm, and stops terminals from interfering with each other. `global` stays a first-class command for FPM, Valet and IDEs.

**Acceptance:** two terminals in different projects keep different `php -v` output, `cd` adds no visible latency, and the migration is tested in `05_shell.bats`.

## Phase 4: Features

Rough priority order. Confidence in brackets.

1. ✅ (4a, 2026-10-03, [[concepts/doctor]]) **`phpswitch doctor`** [high]: PATH order (system, MAMP or Herd PHP ahead of Homebrew), broken links, FPM running as root, root-owned files in the Cellar, missing or duplicate rc hooks, mismatch between the linked and active version.
2. ✅ (Phase 3a) **`local` / `global` / `use` subcommands** [high]
3. ✅ (4c, 2026-10-03) **Shell completions** for zsh, bash and fish [high]. The formula line waits for a release; see [[concepts/release-and-update]].
4. ✅ (already existed, tested in `01_core.bats`) **`--json` output** [high]
5. ✅ (4d, 2026-10-03; see [[concepts/auto-switch]]) **Composer constraint resolution** [medium]. The plan said "highest"; implemented as historical-first, then *lowest* satisfying, so working projects never move: resolve `^8.1 || ^8.2` or `>=8.1 <8.4` to the highest installed version that satisfies it.
6. ⏸ **Deferred: needs the user's decision.** **Valet / Herd awareness** [low-medium]: detect Valet and offer to delegate `global` to `valet use`.
7. ⏸ **Deferred: needs the user's decision.** **PECL extension install per version** [low]: `phpswitch ext install redis`. PECL varies a lot between versions, so treat this as experimental.

## Cross-cutting (fold into any phase that touches the code)

**Done in 4b (2026-10-03):** sudo reduction and non-interactive safety. `--yes` already existed; prompts are now EOF-safe, the menu refuses to start without a TTY, and unknown arguments exit 2. See the AGENTS.md section on privileges and prompts.

- ✅ **`shell_update_rc` (2026-10-03):** `shell_detect_shell` now prefers the login shell (`$SHELL`), which fixes every caller: rc choice, reload scripts and messages. rc files are replaced atomically through `utils_replace_file_contents`, which follows symlinks and keeps the file mode. The 3b migration was also moved off a non-atomic `>` write. Leftover: zsh users who used `--switch` before this fix have a stale, harmless PATH block in `.bashrc`.

- **Reduce sudo (F8):** print the exact fix command instead of escalating. Keep `sudo` only for `/usr/local/bin` installs, and only when the user asks for it explicitly.
- **Non-interactive mode:** `--yes` / `--no` flags, and auto-detect when there's no TTY (`[ -t 0 ]`), so prompts never hang in CI or scripts.
- ✅ (4e, 2026-10-03; pure move verified by `declare -f`) **Split `commands.sh` (F9):** done as `commands.sh` (dispatch), `menu.sh` and `self-manage.sh`. The original plan was: `cmd/dispatch.sh`, `cmd/menu.sh`, `cmd/install.sh`, `cmd/update.sh`. Update the module order in `build.sh` and in [[architecture/module-pipeline]].
